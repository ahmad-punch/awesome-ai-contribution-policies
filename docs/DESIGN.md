# Design

The main decision is to keep one flat, sorted JSON array as the only source of truth and generate the README from it, instead of maintaining a hand-written awesome list. A flat file is trivial to diff, review and consume from any language (`jq`, a script, an agent reading it before opening a PR), and the JSON Schema turns vague prose into fields a tool can act on: whether agents are allowed, which disclosure format to use, and whether an AI `Co-authored-by` trailer is required or forbidden. The trade-off is that real policies are nuanced and the enums flatten them. Godot is filed as a ban although it allows menial AI use, and the Linux kernel is one entry although `drivers/staging` is stricter than mainline. We accept that loss and push nuance into `quote`, `gates` and `notes`, with `quote_kind` marking whether the text is copied verbatim or summarised, and `source_url` always pointing at the policy so readers can check the real wording. Generated output is committed (not built at publish time) so the list renders on GitHub, and CI fails if it drifts from the data.
